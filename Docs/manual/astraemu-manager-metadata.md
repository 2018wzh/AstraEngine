# AstraEMU Manager 元数据与游玩状态

## 启动与设置

Manager 先显示缓存资料库，不自动加载核心或刷新游戏。点击“刷新核心”后，固定原生线程加载程序目录与用户数据目录中的 `cores/`，不随之识别游戏；核心就绪后再手动扫描或添加游戏。七核心范围和操作规则见[客户端手册](astraemu-client.md)。每个核心位于 `cores/<stem>/` 子目录，子目录内恰好一个 `astra_emu_`（Unix 为 `libastra_emu_`）前缀的核心库，加上依赖、`Resources/`、`licenses/` 与 `core.json`；同名子目录以用户数据目录为准。加载复用 C ABI v3、descriptor 和 capability 校验；坏核心、目录结构错误（`ASTRA_EMU_CORE_LAYOUT`）和重复 `plugin_id` 保留诊断，其他唯一核心继续可用。安装、更新或卸载核心后重启 Manager 生效，不做运行中热替换；不要在运行期间移动或替换游戏文件。

FVP 的脚本与资源包按原版规则从游戏目录直接读取，不递归加载备份等子目录中的同后缀文件。启动失败会保留诊断，直到下一次相关操作更新状态。

原生核心自行打开系统音频设备。Manager 不提供 NullAudio 测试后端，设备初始化失败保留原生错误，不自动降级。

游戏画面显示在 Host 工具栏下方，并保持原始宽高比。返回管理器、运行时诊断和视觉滤镜位于独立工具栏中，不遮挡游戏自身的按钮。FVP 清理空存档槽时允许文件不存在，其他文件系统错误仍会中止游戏并显示诊断。

Manager 使用 SQLite schema 5，保留并迁移 schema 4 的资料库与模拟器选择。游戏的原生存档由核心管理，与 Manager 数据分开。外观页保存主题、配色、密度与视图；选择系统主题时响应 Windows 主题变化。手柄设置可保存为全局默认，也可为选中游戏单独覆盖。清除逐游戏设置后恢复全局映射；修改输入或翻译设置前先退出游戏。

滤镜页提供原画、缩放、锐化与 Anime4K 2×，也可加载 Magpie format 4 HLSL。加载后调整参数并保存；编译或保存失败会显示错误并保留旧有效效果。游戏内菜单使用同一组预设。外部效果只接受当前解析器支持的指令，未知指令会报错。Windows 发布包将锁定版本的 `dxcompiler.dll` 与其依赖 `dxil.dll` 放在 Manager 可执行文件旁边；未设置 `ASTRA_EMU_DXC_PATH` 时按可执行文件目录查找，不搜索当前工作目录或系统 PATH。设置该变量时必须指向通过校验的 `dxcompiler.dll`，失败会显示诊断，不改用 CPU 编译。

翻译页先保存 endpoint、协议、模型、目标语言、timeout 和 secret，再点击连接测试。secret 存入平台 keyring，测试在后台请求模型列表，不发送游戏文本。默认 timeout 为 15 秒，上下文固定限最近 8 段、6000 字符。FVP 暂不支持文本替换，游戏继续使用原有字体和正文。

## 元数据

Manager 扫描授权目录时调用已安装 Family 的 probe。扫描不会执行脚本，也不会把路径、文件 hash、脚本文本或素材上传。family probe 与作品匹配是两条独立链路，外部元数据不能修改 family binding。

Manager 的所有联网功能（VNDB、Bangumi、AstraEMU 元数据同步、核心在线下载、实时翻译）共用 设置→联网与资料 中的“允许联网”开关，该开关持久保存，默认关闭。未允许时这些请求返回 `ASTRA_EMU_NETWORK_PERMISSION_REQUIRED`（“需要先在 设置→联网与资料 中允许联网”）。Bangumi 搜索不强制 token；同步游玩状态需要 access token。token 写入平台 secret store，首次发起 Bangumi 请求时才读取。

在游戏库选中作品，打开详情顶部的“关联 / 更换作品”。选择 VNDB 或 Bangumi，输入作品名、原名或译名后按 Enter 或点击“搜索作品”，再根据标题、别名、发售日和开发商选择“关联此作品”。无需查找或填写外部 ID。关联操作重新向 provider 获取该候选的元数据，成功后保存关系和快照；卡片与详情显示关联标题，已有自定义标题优先。

搜索每次最多返回 10 项，关键词不能为空或超过 256 个字符。请求在后台执行，同一作品同时只处理一个请求；空结果和请求失败都会显示状态，用户可修改关键词后重试。候选只属于发起搜索的作品，切换作品不会把结果关联到另一安装。“刷新”更新当前数据源已经关联的条目，不重新进行名称搜索。

详情中的“解除关联”只移除当前作品与所选数据源的关系，不删除安装或游戏存档。旧快照不再用于标题和详情展示；没有其他关联来源时显示导入标题。

安全封面默认启用。“下载敏感封面”开关持久保存；关闭时，带 VNDB sexual/violence 或 Bangumi `nsfw` 标记的图片不会下载，也不会写入缓存。下载过程拒绝重定向和非 HTTPS 域名，并限制 MIME、响应大小、像素尺寸和解码预算。

界面先显示封面占位，再按可见范围异步读取本地图片；已完成的旧任务不能覆盖重排、筛选或更换后的作品。读取标题、关联快照和游玩统计使用同一个批量数据库快照，保留自定义标题优先，以及 VNDB → Bangumi 的元数据来源顺序。

作品已经关联 Bangumi 后，可设置 `wish`、`doing`、`collect`、`on_hold` 或 `dropped`，填写 1 到 10 分和私密备注，再点击 **Sync play status**。Manager 把请求交给后台 worker，并在界面显示结果；429、401、超时或 schema mismatch 不会触发无限重试，需要用户显式重试。

正式发布流程尚未完成；元数据接口的局部测试不代表商业发布许可已获确认。

## 游玩时间与历史

Manager 在启动游戏时开启一条游玩会话，离开游戏或关闭 Manager 时结算，并写入本地 Library。封面卡和 inspector 显示累计游玩时长和最近游玩时间；inspector 还提供逐条会话历史。异常中断的会话可能没有完整结束时间，不据此推算未记录的游玩时长。游玩记录只保存在本地，不上传，也不进入发布报告。

## AstraEMU 元数据

兼容性、推荐配置、核心目录和汉化补丁目录来自公开仓库 `2018wzh/AstraEMU-metadata`，发布地址为 `https://2018wzh.github.io/AstraEMU-metadata/v1/`。允许联网时，Manager 在首帧显示后于后台同步一次；在 设置→联网与资料 点击“立即同步”，或开启“允许联网”时也会同步。同步按 ETag 与 sha256 只下载有变化的文件，全部校验通过并能解析后才替换数据目录下的 `metadata/`；校验或写入失败会显示通知并保留原有数据。数据有变化时提示“元数据已更新”，没有变化时不提示。发布包自带一份 `metadata/` 快照，比本地缓存新时优先使用快照；两者都没有时显示“未同步”。

兼容性徽章与筛选使用社区分级：完美运行、可通关、有瑕疵、仅能启动、无法运行；没有记录的作品不显示徽章。VNDB 是游戏与版本标识的唯一权威源：游戏用 vID（`v123`）标识，具体发行版本用 rID（`r1234`）标识。记录按“发行版本 + 当前所选模拟器”匹配，同一版本在不同模拟器下可以有不同分级。作品需要先关联 VNDB；在详情的“兼容性”中点击“获取版本列表”并选择发行版本，选择会持久保存。没有选择时，如果数据库中该作品只有一个发行版本就直接使用它，有多个时提示“选择发行版本以查看兼容性”。Bangumi 只用于游玩进度，不参与匹配。

同一发行版本与模拟器有推荐配置时，游戏设置显示推荐摘要和“套用”。套用把配置中的每一项写入这部作品的单独设置；任一项对当前模拟器无效时全部恢复原样，并提示 `ASTRA_EMU_PRESET_INVALID`。推荐配置指定的汉化补丁在补丁列表中标为“推荐”。

“报告兼容性”打开元数据仓库预填好的 issue 表单，包含 vID、rID、模拟器、平台和版本；作品未关联 VNDB 时按钮不可用，并提示“先关联 VNDB 作品”。维护者审核后由仓库工作流把报告转成兼容性记录。

设置→核心 合并显示已加载、加载失败、待安装/更新/移除和可在线安装的核心；元数据中有更高版本时显示“可更新”。在线安装下载 GitHub Releases 上的核心包，校验大小与 sha256、检查包内路径和 `core.json` 后放入待安装区，提示“核心已下载，重启后生效”，可点“立即重启”。
