# Minori 脚本执行

Minori Family 自持 VM、归档、音频和原生 session。Manager 经 Family API 提交物理输入并接收最终帧、PCM 和诊断；不执行 Minori 私有指令。当前进度与真实游戏阻塞见[实施状态](../../status/implementation-plan.md)。

## 控制流与输入

`chain` 是尾链式脚本切换，没有调用栈或 return。目标限 `minori:/scr/` 下的直接 `.sc` 文件，可带已存在的标签；切换前读取并解析新脚本，成功后清除 local 变量、保留 global 变量。缺文件、非法标签和路径穿越直接失败。

`set`、`setglobal` 接受三操作数赋值和五操作数整数表达式，先查 local 再查 global。`wait` 的整数单位为 10 ms，状态保留原始 tick 与换算后的毫秒。时间、输入和选择等待由 Family session 推进。

`message` 使用保留空字段的 space/tab tokenizer。前四项分别是消息 id、voice identity、speaker、正文首段，后续字段用单个空格连接。短消息沿用原解析器的默认字段。`select` 保存选择焦点，确认键或有效指针点击提交分支；读档恢复同一焦点。文字在 Family 内经共享文字能力生成绘制命令，再由 GPU 合成，正文不进入诊断日志。

## Stage 与绘制

`transition` 保存后续 stage 的模式、资源和时长配置。`stage` 按原生参数结构保存：

- 一至两个冒号分隔的前景资源，`*` 表示空项，保留顺序。
- 可选的两个有符号参考坐标。
- 背景资源及其两个坐标。
- 最多十组立绘文件名和 `position[,resource_parameter]`；省略第二个参数时为 0。

参数列表允许一个末尾空字段，内部空字段、无效整数和不安全资源名拒绝。文件名中的逗号不会被拆成立绘参数。解析完整且校验通过后才替换当前 stage；不再将立绘参数丢弃后转换成 `(0, 0)` 图层，也不通过毫单位转换截断坐标。

`MinoriRuntimeState.stage` 是播放与恢复共用的场景状态。Family 的 `Scene` 使用 SDK `TextureCache` 和公共 `WgpuOffscreenRenderer`，正常帧与读档重建走同一入口。当前已接入单前景资源、背景和整数定位；默认中心/底部原点的静态 PNG 立绘已接入：使用 PNG 的 `ol`、`ot`、`or`、`ob` 文本字段，按原生公式计算位置和可见高度，复用 SDK 纹理缓存及 GPU 裁剪矩形。无字段时使用原生零边界；重复、非法整数或超限文本明确拒绝。单资源为主前景，双资源按冒号前缀、主前景解析；绘制顺序为背景、立绘、主前景、固定原点的前缀层。主前景使用 reference position，`_sc.png` 按编码颜色空间作 Screen 混合；`_ov.png` 的原生模式尚未实现，返回 `ASTRA_EMU_MINORI_STAGE_BLEND`。存在同名 SQZ 时返回 `ASTRA_EMU_MINORI_STAND_ANIMATION`。非默认原点模式仍待接入，不能忽略额外资源或附加参数后声称支持。新的失败帧不覆盖此前有效像素。

已有 `CrossFade2` 时间状态与最后可见帧保存独立于 stage；渲染层叠加实际可见资源和 alpha。未知效果、非法资源及不支持的时间参数拒绝。`.panel 1` 使用消息面板资源，其他形式仍须按实际 handler 继续接入。

原生入口的后续静态分析补充了以下边界，尚未作为完整绘制实现：

- `CommandStage` 的执行函数 `sub_450FE0` 经 `sub_457820`、`sub_45AC10` 分别调用前景加载 `sub_42E900` 与立绘加载 `sub_431030`。前景参数中的冒号分隔两个独立图像缓冲；没有冒号时使用主缓冲，有冒号时前半部分进入另一缓冲、后半部分进入主缓冲。它不是按时间交替的 `CrossFade2` 资源列表，不能直接复用后者的播放规则。最终层次与坐标绑定仍需核对。
- 立绘的 `resource_parameter` 传给 `sub_430980`，参与资源可见高度裁剪，不是缩放比例。该函数先扣除图像对象的末端边界值，再在差值为正时减少可见高度；裁剪覆盖全部高度时加载失败。`sub_431030` 根据资源左右边界和宽度计算横向中心，根据裁剪后的高度计算底部对齐；独立的原点模式可以改用显式位置。边界值来自 PNG 文本字段 `ol/ot/or/ob`。默认原点已接入；`Wind` 和 `StandOriginTopLeft` 对原点模式的影响仍需接入原生配置，不能直接把参数加到屏幕坐标。
- PNG 加载后会尝试读取同名 `.sqz`，`sub_422410`、`sub_422310` 和 `sub_416A00` 将其接入动画资源。文件不存在与存在但格式损坏必须区分；只显示 PNG 不能算完成带 SQZ 的动画。已核对 GARbro 的 Musica SQZ reader，但帧时序仍以实际原生执行为准。
- 冒号前半资源还携带独立混合模式：`sub_418FF0` 对 `_sc.png` 后缀作不区分大小写匹配，选择模式 1；`sub_419F00` 将该模式分派到 `sub_4189C0`。后者使用 `sub_4188F0` 初始化的查表实现 Screen：先把源通道乘有效 alpha，再计算 `255 - (255 - dst) * (255 - src) / 255`，保留目标 alpha。不能把该资源当成普通不透明前景覆盖。公共 GPU 后端承接已有 `BlendMode::Screen` 契约；Minori 已接入双资源静态 stage，模式 2 的 `_ov.png` 保持显式拒绝，不映射成普通 Alpha 或 Multiply。

以上分析使用本页关联格式文档中已固定身份的原版入口。数据库与反编译中间文件留在 ignored 私有目录，不进入产品资源或公开测试。

## 音频

资源后缀沿用 `resource[volume,pan]` 规则。BGM 和三个 SE bus 由 Family 音频 worker 执行；`*` 是停止请求，保留 fade-out 参数。资源统计与运行时使用同一停止符，不将其列为缺失文件。非循环音频完成、音量与淡出状态由实际混音进度决定。

解码和混音复用 SDK/Engine 能力；Host 消费有界 PCM 队列。关闭先取消阻塞写入，再等待 worker 结束。单元测试和静态资源命中不能替代真实设备播放验收。

## 保存与恢复

VM 数据使用 `astra.emu.minori.runtime_state.v8` 和 postcard，包含脚本身份、PC、变量、等待、完整 stage、transition、效果时间状态、面板和音频等字段。v7 及更早数据直接拒绝，不迁移旧图层表示。stage 的资源角色、名称、序列长度和立绘数量在保存、解码和恢复边界校验。

Family 存档容器另外保存当前显示消息、等待余量和音频快照。恢复先验证游戏及脚本身份，再构造候选 VM、GPU 场景和音频状态；场景重建失败不得将其标为恢复成功。归档解密后的完整素材和 GPU 资源不进入 VM 数据。损坏存档读取失败不得覆盖原文件。

回归覆盖完整 stage 参数往返、PNG 三类文本编码、重复/损坏字段、裁剪边界和坐标溢出、非法恢复不修改 live VM、GPU 定位与恢复画面一致、失败后保留此前像素。GPU 立绘测试还验证裁剪不修改缓存原图，减少裁剪后可重新显示完整高度。真实《夏空的英仙座》的双资源 stage、立绘附加参数、剩余演出和结局仍保持开放。

图层排序由原生 LayerManager 按 layer id 升序执行，独立前缀层 940120 位于主前景之后。背景与立绘调用的层参数为 15，主前景的静态层为 940100，动态前景位置组为 940110。Family 复用公共 GPU 命令，不另建像素合成器。同一图片可出现在多个图层，绘制 ID 与纹理缓存 URI 分离。GPU 回归覆盖 Screen 像素、前景遮挡立绘、固定前缀原点、重复纹理、原生存档恢复和失败帧保留；这些检查不替代商业游戏长流程。
